**Secondo gruppo di miglioramenti — 30 ottobre 2026**

Il [terzo gruppo](WORKSPACE_AND_TERMINALS_2026-10-30.md) aggiunge policy filesystem,
controllo delle revisioni dei file e sessioni PowerShell persistenti e cancellabili.
Le questioni aperte in fondo a questo documento descrivono lo stato del secondo gruppo.

Completati i punti runtime, root Git, persistenza JSON e risultati asincroni
rimasti nella prima review.

- **Runtime:** dipendenza Electron fissata a 45.1.0 e lockfile aggiornato.
  Verificata anche la versione del binario effettivamente scaricato.
  L'audit npm completo ora riporta zero vulnerabilità; risultato conservato in
  `npm-audit-after-2026-10-30.json`. Il precedente audit rimane come evidenza storica.
- **Compatibilità:** consultate le [breaking changes ufficiali](https://www.electronjs.org/docs/latest/breaking-changes),
  in particolare le restrizioni dei preload sandbox di Electron 45. Il preload
  dell'IDE importa solo Electron. Adeguato il listener console dei test alla
  firma corrente e verificato il percorso renderer/preload/IPC sul nuovo runtime.
- **Git:** lo stato espone `repoRoot` e tutte le operazioni del repository
  risolvono la root reale, anche quando l'IDE apre `Repository/Apps/Sample`.
  Apertura file, contenuti HEAD, diff, staging e discard usano la stessa base.
  Il pannello Git riguarda l'intero repository, inclusi file esterni alla
  sottocartella progetto; l'esplora file continua a mostrare il progetto aperto.
- **Persistenza:** sessioni e recenti usano scritture asincrone su un file
  temporaneo nella stessa directory, flush e sostituzione mediante rename.
  Una coda per destinazione mantiene l'ordine delle richieste. Anche letture e
  cancellazioni rispettano le scritture pendenti, e la chiusura dell'app attende
  la coda. I temporanei hanno nomi casuali e creazione esclusiva.
  Le sharing violation transitorie di Windows ricevono un numero limitato di
  tentativi; il file valido non viene cancellato come ripiego.
- **Concorrenza UI:** ogni workspace ha una generazione e ogni categoria di
  richiesta una sequenza. Risultati superati di albero, Git, apertura file,
  salvataggio e diff non modificano il workspace corrente. Aprire un nuovo
  progetto svuota il vecchio stato Git; se l'apertura fallisce viene ripristinato
  il contesto precedente. Le richieste da categorie indipendenti non si invalidano.

**Verifiche**

`npm run typecheck`, `npm test` (14 test), `npm run build` e `npm run test:desktop`.
Il test desktop usa un repository temporaneo con progetto annidato; verifica
la root restituita, il contenuto di HEAD, apertura dell'editor, sostituzione e
salvataggio, e l'isolamento tra finestre. I test di persistenza controllano
lettori concorrenti, ordine delle scritture, cancellazione seguita da salvataggio,
errore di scrittura e assenza di JSON parziali.

Rimane l'avviso di dimensione del chunk Monaco, caricato solo entrando nell'IDE.
Non sono stati eseguiti installer NSIS/portable, build iOS firmate o distribuzioni
su dispositivi.

**Ancora da affrontare**

Policy di autorizzazione dei percorsi filesystem per workspace; rilevamento dei
conflitti con modifiche esterne ai sorgenti; terminali persistenti con PTY e
cancellazione dedicata; ulteriore separazione di App.tsx e contratti IPC tipizzati.
Le scritture atomiche proteggono l'integrità dei JSON di sessione/recenti, non
costituiscono un protocollo di lock tra processi diversi e non rendono atomici i
salvataggi dei file sorgente. SDK manager, canvas e debug restano incompleti.
